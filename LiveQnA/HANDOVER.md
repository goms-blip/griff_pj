## 1. 이게 뭔가

행사장에서 참가자가 **앱 설치·로그인 없이 QR만 찍고** 세션에 질문을 남기고, 좋아요로 질문을 위로 올리는 도구입니다. 강연자·진행자는 별도 화면에서 질문을 좋아요순으로 보며 답변 처리·숨김을 합니다.

**가장 가까운 실전 투입:** 언리얼 페스트 서울 26 (2026-08-20 ~ 08-21, 4개 룸, 공개 세션 29개)

### 세 종류의 화면

| 화면 | 누가 | 주소 |
|---|---|---|
| **참가자** | 청중 | `#/r/<행사코드>/<룸번호>` (룸 QR, 권장) 또는 `#/s/<세션코드>` |
| **룸 운영자(스피커)** | 룸에 상주하는 진행자 / 무대 PC | `#/ra/<행사코드>/<룸번호>` (운영자 토큰으로 1회 로그인) |
| **강연자·진행자(세션 단위)** | 특정 세션 발표자 | `#/a/<세션코드>?token=<세션 admin_token>` |
| **운영자 콘솔** | 우리 | `#/admin` (운영자 토큰 입력) |

**룸 화면 두 개(`#/r/…`, `#/ra/…`)는 같은 시각 판정을 씁니다.** 룸당 각각 한 번만 열어두면 세션 전환을 사람이 챙길 일이 없습니다.

### 🔴 인수인계 직후 반드시 할 것

1. **`ADMIN_CONSOLE_TOKEN` 교체.** 현재 12자로 짧습니다. 이 토큰 하나로 **프로젝트 생성·삭제와 참가자 개인정보가 든 엑셀 다운로드**가 전부 가능합니다.
   ```bash
   openssl rand -hex 32
   vercel env rm ADMIN_CONSOLE_TOKEN production --yes
   printf '%s' '<새값>' | vercel env add ADMIN_CONSOLE_TOKEN production
   # 재배포 필요. DB는 건드리지 않아도 됩니다.
   ```
2. **Preview 환경에 `ADMIN_CONSOLE_TOKEN` 재등록.** 과거 작업 중 Production만 남고 Preview 등록이 사라졌습니다. Preview 배포를 쓸 계획이면 다시 넣으세요.
3. **service_role 키가 어디에도 커밋되지 않았는지 확인.** 저장소가 공개입니다.

### 4-1. 스트레스 테스트 결과 (2026-07-30)

버리는 테스트 프로젝트로 측정하고 삭제했습니다. **모든 시나리오에서 실패 0건.**

| 시나리오 | 동시 10명 | 동시 100명 (p95) |
|---|---:|---:|
| 첫 진입(index.html) | 53ms | 1,125ms |
| 룸 타임테이블 | 92ms | 618ms |
| 행사 랜딩 | 106ms | 704ms |
| 질문 목록(Supabase 직결) | 26ms | 323ms |

- **Realtime 동시 구독 300개까지 실패 0** — 참가자 1명 = 구독 1개이므로 룸당 수백 명은 무리 없습니다.
- 테스트 중 **함수가 미국 동부에서 실행되던 것을 발견**해 서울(`icn1`)로 고쳤습니다. **API 응답이 약 10배 빨라졌습니다**(랜딩 1,111ms → 106ms). `vercel.json` 의 `regions` 를 지우면 원복되니 주의하세요.
- 첫 진입 문서에 CDN 캐시를 붙여, 세션 시작 시각에 QR 스캔이 몰려도 엣지가 대신 응답합니다.
- 📏 첫 진입 처리량이 ~155 RPS에서 평탄한데 이는 **테스트 PC의 회선 포화**(77Mbps)이지 서버 한계가 아닙니다. 실제 상한은 이보다 높습니다.

> 🐞 **이 테스트에서 질문 도배 제한이 작성 시점부터 무효였던 것이 드러났습니다.** anon으로 20건을 연속 등록해도 전부 통과했습니다. 원인은 `SECURITY DEFINER` 함수 안에서 `current_user` 로 호출자를 판별한 것(그 안의 `current_user` 는 함수 소유자입니다). 수정본이 `fix_question_rate_limit.sql` 이고, **아직 실행 전입니다.**
> 한도는 10 → **60건/분**으로 올렸습니다. 이 제한은 IP 단위인데 행사장 와이파이는 NAT라 **룸 전체가 한 IP**로 보이기 때문입니다. 10건/분이면 정상 관객이 막힙니다.

## 4. 행사 당일 운영 절차

### 행사 전 (D-7 ~ D-1)

1. **세션 데이터 확정** — 콘솔에서 엑셀 일괄 등록 또는 구글 시트 연동. 날짜·시간·트랙·강연자 확인.
2. **트랙(룸) 순서 고정.** 🔴 룸 QR 번호가 트랙 정렬 순서입니다. **QR 인쇄 후 순서를 바꾸면 QR이 다른 룸을 가리킵니다.**
3. **공개 여부 확정** — 비공개 세션은 참가자에게 404입니다.
4. **룸 QR 발급·인쇄** — 콘솔 → 프로젝트 상세 → **`룸 QR` 버튼** → 룸마다 PNG 다운로드(또는 전체 일괄).
   PNG에는 QR 아래에 룸 이름이 함께 들어가 있어 그대로 인쇄하면 됩니다.
   주소 형식은 `https://liveqna-app.vercel.app/#/r/<행사코드>/<룸번호>` (언리얼 페스트 26 기준 `feb8a3`, 1=Harmony Ballroom 1 … 4=Atlas)
5. **룸 운영자 화면 준비** — 룸 PC/태블릿에서 `#/ra/<행사코드>/<룸번호>` 를 열고 운영자 토큰으로 1회 로그인. 이후 세션 전환은 자동입니다.
   (특정 세션 발표자에게만 권한을 주려면 세션 카드의 **관리자 URL**을 쓰세요. 세션마다 다릅니다.)
6. **리허설** — 실제 폰으로 QR을 찍어 질문 등록·좋아요·실시간 반영까지 확인.
7. **스트레스 테스트** (①번 숙제).

### 행사 중

- **평상시 할 일 없음.** 세션 전환은 시각 기준 자동입니다.
- 부적절한 질문 → 강연자 대시보드에서 **숨김** (삭제 아님. 숨김은 참가자 화면에서 즉시 사라집니다)
- 참가자가 "세션을 찾을 수 없습니다" → 대개 **비공개 상태**입니다. 콘솔에서 공개로 전환.
- 참가자가 대기 화면에서 안 넘어감 → 세션 시간이 잘못 입력됐는지 확인.

### 행사 후

- 세션별·프로젝트별 **엑셀 export** 로 질문 아카이브.
- 필요 시 세션 비공개 전환.

## 5. 장애 대응

| 증상 | 원인 후보 | 조치 |
|---|---|---|
| 모든 API가 503 `PGRST002` | Supabase Data API 비활성 | 대시보드 → Integrations → Data API → Enable |
| 콘솔 로그인이 계속 401 | Vercel의 `ADMIN_CONSOLE_TOKEN` 이 알고 있는 값과 다름 | env 재설정 후 **재배포** |
| 참가자 페이지에서 질문이 안 보임 | 세션이 비공개 / RLS | 공개 전환. 미리보기는 `?pv=<admin_token>` |
| 질문 등록이 "실패했어요" | 금지어·길이·도배 제한 | 사유별 문구가 뜹니다. 도배 제한은 60초 10건 |
| 좋아요가 `rate_limited` | 같은 IP에서 60초 60표 초과 | 행사장 공용 와이파이면 NAT로 수백 명이 같은 IP입니다. 정상 동작이나, 한도 조정이 필요하면 `fix_high_findings.sql` 참고 |
| 배포가 거부됨(cron) | Hobby 플랜 크론 제한 | `vercel.json` 크론을 하루 1회로 |
| 룸 화면이 세션을 안 바꿈 | 세션 `starts_at`/`ends_at` 이 비었거나 잘못됨 / 비공개 | 콘솔에서 시간·공개 여부 확인. 시간 정보가 없는 세션은 자동 전환 대상이 아닙니다 |
| 룸 QR이 엉뚱한 룸으로 감 | 인쇄 후 **트랙 순서가 바뀜** | 트랙 순서를 원래대로 되돌리거나 QR 재발급 |
| 룸 운영자 화면이 로그인만 반복 | 콘솔 토큰 불일치 / sessionStorage 초기화 | 운영자 토큰 재입력. 탭을 닫으면 다시 입력해야 합니다 |

**롤백:** Vercel 대시보드 → Deployments → 직전 배포 → Promote to Production.
